# Windows 按需绘制与待机降耗验收

日期：2026-11-01。对应[性能计划](windows-performance-plan.md)第 4 步。关联：[资料索引](README.md) · [实施记录](implementation.md) · [第 3 步地表性能](windows-simple-surface.md)。

## 已实现的行为

本轮属于所有地图共用的编辑器开发，仅调整显示调度，不修改地图、工程格式、历史、素材、采样、单片地形或 Cocos 导出。三个显示档位均启用按需绘制。

- 没有画面变化需求时，停止 RAF 和重复提交；加载期间也不轮询，资源回调就绪后唤醒。保留最后一帧画面及 Draw／模型面数。
- 只影响状态栏的通知不会唤醒三维画面；显示订阅比较实际显示输入，不复制地图或纹理字节。
- 相机拖动、滚轮、投影、方向过渡、定位、有效 WASD／QE 按键、笔刷、图层、选择、预览、取消、撤销／重做及窗口／DPR 变化请求下一帧，同帧多个通知合并。绘制中出现新失效仍保留下一帧。
- 地表纹理解码、水纹解码、模型批次／惰性 LOD、草实例和据点幽灵完成后请求刷新。旧工程／旧任务继续沿用原有版本校验；视口释放后回调不能重新启动循环。
- 水面实际提交颜色通道时继续调度；近景草实际提交且保守包围球触及 80 米淡出范围时继续动画。只在文档中存在河流或草层，不会永久占用循环；隐藏图层或转离视野后可睡眠。
- 动画判断使用渲染器可见性和包围体，不是逐像素遮挡检测；被其他物体完全遮住但仍提交的水／草可能继续调度，草包围体覆盖透明区域时也可能保守多绘制。
- 页面隐藏时取消下一帧；桌面主进程另通过只读布尔事件通知最小化／隐藏／恢复／显示，避免仅依赖 Chromium 可见性。preload 缓存最新状态，订阅立即回放，取消订阅后不再通知；不增加窗口控制或任意 IPC 权限。恢复时补画并重新判断动画。唤醒首帧不把整个待机间隔计入相机过渡或 FPS。
- 连续刷新统计每秒发布；150 毫秒内的短暂停顿合并，不反复推动 React 活动／静止状态。超过该间隔显示“静止 · 按需刷新”，连续绘制恢复后重新累计 FPS，首个统计周期显示“—”。150 毫秒只是文字状态合并，GPU 提交和 RAF 已经停止。

## 验证方法

```sh
npx vitest run tests/demand-frame-loop.test.ts tests/display-quality.test.ts tests/simple-surface.test.ts tests/performance-diagnostics.test.ts tests/navigation-resources.test.ts tests/water-rendering.test.ts tests/surface-performance.test.ts tests/surface.test.ts
npm run test:demand-render
npm run build
npm run test:demand-render-desktop
npm run test:windows-performance -- --baseline-only --quality=fast
```

源码 WebGL 夹具为程序构造的测试地图，不是正式地图作品：覆盖空场景零提交、滚轮／WASD／方向动画／定位、真实鼠标笔刷与撤销重做、受控延迟的贴图／据点幽灵、预览取消、窗口调整、可见水面／近景草、隐藏图层、视锥外动画、1025² 工程替换和资源释放。

桌面专项通过真实 dist EXE、独立配置和真实首页创建 513² 空白／内置示例，不接管用户工程。空白无操作每轮 15 秒、三轮读取累计提交计数；同时检查静止文本与文档／历史哈希。Playwright 调试连接下实测即使关闭聚焦模拟，`document.visibilityState` 仍可能保持 visible。因此最小化用真实 BrowserWindow 状态和主进程发给产品的只读可见性通知判定，页面可见性照实保留在报告，不能虚构 hidden；同时检查实际提交计数停止及恢复。

性能工具 `sample` 显式维持连续渲染，并在每条结果写入 `scheduling=forced-continuous-diagnostic`，结束后恢复按需绘制。静止连续采样只表示渲染吞吐；待机专项不调用 `sample`。固定相机平移用于前后可复现对照，不代替所有实际编辑操作。静态 5 秒预热等待期间遵循产品按需调度；实际 15 秒测量才强制连续提交，不能把等待期当作连续 GPU 热身，也不据此推断不同轮次的 GPU 频率／功耗相同。

## 本轮结果

原 `dist/mapEdtor-v0.2.0` 已更新；`app.asar` SHA-256 为 `32fa08b1795c739ca29f2b410b8c41f7ee68d69c03bc5a90a2e60b71017a5559`。本机 i7-7700HQ、HD 630／ANGLE D3D11、Windows 10、125% 缩放、交流电，未强制独显。待机初始窗口内容 1600×1000，CSS 视口 1038×873，流畅绘制缓冲 778×654；功能检查中按步骤调整窗口和档位，不与固定性能条件混报。

- [源码 WebGL 专项](../../test-results/tests/demand-render-1793517696950/report.json)通过 18 组检查，无页面错误；另断言延迟贴图就绪能够单独唤醒，最终释放几何计数为 0。四层地表、保存与导出行为沿用第 3 步，不在本轮重做画质算法。
- [真实 dist 按需绘制报告](../../test-results/tests/demand-render-desktop-1793518592084/report.json)通过：空白三轮各 15 秒，累计提交均保持 4→4，新增 0 帧、待执行 RAF 为 0，静止文本正确；地图编码／历史哈希不变。启动及异步资源就绪的前 4 帧不计入待机。
- 同一桌面报告通过真实滚轮／投影／格线／笔刷／撤销、离开画布清除悬停、调整窗口、三个档位切换、据点选择及返回首页。可见水面持续提交；最小化 1.5 秒新增 0 帧且原生可见性为 false，恢复后继续动画。仅通过临时显示开关隐藏水草后的示例 15 秒新增 0 帧，内容／历史哈希一致；随后恢复所有图层。隐藏图层的结果只用于调度验证，不作为完整示例操作性能。
- 调度、档位、导航、地表、水面和诊断相关单测 54／54 通过；类型、源码引用检查通过。原全量单测的素材 LOD 阈值问题未修改，本轮不宣称全量单测通过。

### 连续渲染及操作性能

[本轮正式性能报告](../../test-results/tests/windows-performance-2026-11-01T07-39-16-486Z/report.json)与上述待机报告使用相同 app.asar。固定内容窗口 1600×1000、相机位置 `[700,870,1050]`／目标 `[0,32,0]`、流畅档 778×654 缓冲、513²、2048×2048 米、默认 HD 630；每段等待预热 5 秒，实际连续采样 15 秒、重复三轮。共 12 段有效、无错误，各条均有强制连续诊断标记。采样期间未运行其他 WebGL 功能或性能测试。

三轮中位数如下；CPU 为整帧 JS 墙钟时间，不能与 GPU 时间相加。

| 场景 | FPS | P95 帧间隔 ms | CPU 帧 ms | GPU ms |
| --- | ---: | ---: | ---: | ---: |
| 空白静止连续提交（诊断） | 60.08 | 16.90 | 0.30 | 10.62 |
| 空白固定相机运动 | 60.07 | 16.90 | 0.30 | 10.63 |
| 完整示例静止连续提交（诊断） | 50.62 | 23.70 | 1.10 | 17.58 |
| 完整示例固定相机运动 | 50.40 | 46.90 | 1.90 | 17.15 |

空白保持 1 Draw／524,288 面，完整示例保持 51 Draw／772,141 面；未删除内容、降低采样或进一步压缩缓冲。FPS 延续第 3 步本机固定场景目标；本轮主要收益是无变化时免去重复工作，不把 49→50 FPS 的运行差异当成明确的算法提速。完整示例运动 P95 仍为 46.90 ms，长任务和全流程编辑卡顿仍需第 5 步处理。

正常启动发布版的首页、空白／示例创建、原生工程读写、未保存保护和近期记录回归通过；诊断入口默认关闭。最终 dist 的 [125% 模拟缩放切档回归](../../test-results/tests/display-quality-1793519131175/report.json)通过 10 组投影／档位切换及大窗口预算检查，保留镜头、选择、未保存内容和历史；旧上下文释放、单画布／至多一个待执行 RAF、重启偏好正常。

[水面像素回归](../../test-results/tests/demand-render-1793517696950/water-visibility-report.json)的 8 个镜头与停止动画负对照通过，固定时刻稳定、流纹连续且无页面／着色器错误。

历史模型／地表／水面测试夹具已同步新的动画时间及显式连续诊断调度；它们的固定画面和连续吞吐检查不依赖产品待机持续绘制。

## 边界与后续

零提交证明消除了视口重复提交及对应逐帧 JS／GPU 工作，没有直接测量整机瓦数或 GPU 利用率；自动草稿、操作系统合成和其他应用仍可工作。静止不能报告成操作 FPS，无动画画面停在 60 FPS 的历史读数也不能作为新的性能结论。

第 5 步的连续编辑长任务治理和第 6 步的完整 Windows 集成验收未执行。不因本轮按需绘制而宣称所有工程、1025² 操作帧率或所有笔刷已整体达标。
