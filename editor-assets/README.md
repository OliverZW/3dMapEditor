# 地图内置素材

此目录是应用内置素材的唯一来源；源码和测试不保存模型、图片字节副本。

- `models/manifest.json`：城池、要塞、五种树木和草丛的 GLB、基础校正、尺寸、统计与 SHA-256；GLB 内嵌全部模型贴图。各模型 JSON 保存制作元数据。
- `surface/manifest.json`：四层地表颜色图、法线图、缩略图、米制纹理尺度、默认显示参数与 SHA-256。
- `water/manifest.json`：水纹法线及遮罩的尺寸、路径、SHA-256 与基础 PBR 参数。
- `surface/provenance.json`、`water/provenance.json`：现有研究素材的来源和加工记录，保留原研究范围；位置调整不改变素材来源。
- `models/provenance.md`：自制模型与贴图的制作来源。

路径相对本目录，发布时由 Vite 的 publicDir 复制；浏览器 URL 通过部署 base 拼接，不包含 editor-assets 前缀。分类清单作为纯描述使用，IO 读取并校验文件，成功后整组发布。用户工程包与构建输出可以包含素材副本，它们不是素材维护入口。

更换模型时更新对应 JSON；更换贴图时更新对应分类清单。然后执行 `npm run prepare:asset-manifests` 刷新哈希、图片尺寸与模型索引，并运行资源测试。模型 JSON 的尺寸、面数和材质数由制作工具提供，浏览器资源测试会与实际 GLB 核对。Blender 制作工具先写本目录，再为独立制作预览复制派生产物；不会反过来从预览工程加载运行资源。

`npm run prepare:prototype-models` 可重新导出原要塞、草丛原型并刷新清单；应用运行不依赖此工具。地表、水面加工分别使用 `prepare:surface`、`prepare:water`，输出只写本目录。

地形几何、地图权重图、GPU 缓存和着色器属于运行时数据或算法，不作为静态素材存放。

## 内置模型细节层级

五种树木和城池的中远景派生 GLB 位于 models/lod，由 `npm run prepare:model-lods` 从原模型确定性生成。分类清单的可选 lod 描述记录原始内容哈希、派生路径、哈希和面数；不得手工替换后沿用旧哈希。先刷新原始清单，再加工LOD。更新清单工具保留源哈希匹配的派生描述，源文件改变则删除旧描述。

这些文件仅供编辑器显示，按需加载；原始 GLB 仍用于近景、资源详情、工程保存和 Cocos 导出。派生文件复用本工程自制模型和贴图，未引入其他素材。
