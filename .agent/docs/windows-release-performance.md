# Windows 性能集成验收与便携版发布

日期：2026-11-01。对应[性能计划](windows-performance-plan.md)第 6 步。关联：[资料索引](README.md) · [实施记录](implementation.md) · [连续编辑优化](windows-editing-performance.md) · [发布说明](RELEASE_NOTES.txt)。

## 发布范围

所有地图共用的 Windows x64 编辑器更新，沿用原 `dist/mapEdtor-v0.2.0`，不另建版本目录。便携版附带 `发布说明.txt`，文件纳入构建清单；旧包由原构建流程存放于 `test-results/builds/`。最终 app.asar SHA-256 为 `1395c3cf574cbfaefd4e30c768f090649f9a81fa3823b5fc8414b1424c92794b`。

包含前三步的 GPU 诊断、三档画质与简化地表，第 4 步按需绘制及第 5 步连续编辑优化。单片连续地形、原始采样和对象数据、工程格式、共享素材及 Cocos 导出契约保持原约定；测试示例不是正式地图作品。

## Windows 显卡选择

集成预检发现：默认核显在 1025² 流畅空场景约 46 FPS，GPU 约 20.5 ms，仍低于 60 FPS。仅靠主线程优化不能替代硬件路径选择。因此最终 Windows 启动在 ready 之前落实高性能显卡偏好，尊重显式的高性能／低功耗启动选项。依据 [Electron 官方命令行约定](https://www.electronjs.org/docs/latest/api/command-line-switches#--force_high_performance_gpu)，多显卡时选择独显；显式 `--force_low_power_gpu` 仍可请求核显。

本机最终默认启动已确认使用 GTX 1050；未修改 Windows 全局图形设置。设备只有核显或驱动选择不同的情况，不能套用本机独显结果。第 1～5 步的 HD 630 报告按当时默认路径保留，不把选择独显的收益混作同核显算法提速。

[最终显式低功耗路径验证](../../test-results/tests/windows-performance-2026-11-01T12-12-51-501Z/report.json)通过，同一最终构建实际切回 HD 630，4 段快速采样均有效。1025² 流畅空白运动约 43.95 FPS、示例约 36.97 FPS；仅预热 1 秒、采样 2 秒，不作正式性能结论，但确认核显空白仍有 GPU 瓶颈，不能把独显达标泛化为核显达标。

## 设备、输入和方法

本机 i7-7700HQ、约 16 GiB RAM、Windows 10 x64 19045、125% 缩放、60 Hz、交流电和原高性能电源计划。最终 GTX 1050 驱动 31.0.15.2686、ANGLE／D3D11 硬件加速；采样工具不额外传 `--force-discrete`。每份报告记录实际显卡／驱动／后端与 app.asar 哈希。固定内容窗口 1600×1000、CSS 视口约 1038×873，相机位置 `[700,870,1050]`、目标 `[0,32,0]`。流畅绘制约 778×654，均衡 1038×873，高画质 1297×1091；实际尺寸以各报告为准。

513² 空白和示例经真实首页创建；1025² 空白同样真实创建，1025² 示例由[夹具生成工具](../../dev-tools/create-performance-fixture.mjs)按原三角面重采样基础高度、按最近采样扩展权重／密度，使用正式目录存储写入独立工程。对象 ID／数量、尺寸和内置资源身份保持，保留相同 LOD 路径；测试不修改用户地图。

每个档位／采样组合分别测试空白与完整示例的静止连续提交、固定相机平移。各段真实连续预热 5 秒、采样 15 秒、重复三轮；六组串行，采样期间不运行其他 WebGL 功能或性能测试。第 6 步预热已改成显式连续提交，与第 4、5 步静态等待期间按需绘制的方法分别标注。

FPS／P95 来自实际渲染开始的时间戳；GPU 来自异步查询，CPU 是 JS 墙钟，不是利用率，也不能与 GPU 时间相加。待机零提交由单独测试证明，不能作为操作帧率。相机平移不代替实际笔刷、导航和工程操作回归。

513² 空白地形 524,288 面，1025² 为 2,097,152 面，均为单片网格。完整示例保存 946 棵树、2 个据点、1 条河流和 1 层草，固定视口实际有效树 870 棵。513² 示例初始约 10,483 草、51 Draw、772,141 总面；1025² 程序构造示例约 10,705 草、51 Draw、2,347,669 总面。高精度副本因采样及贴地变化不要求派生草数量逐个相同，不能把它称为同一输入的无差别对照；没有通过降低采样、删对象或隐藏内容达标。

## 复现

```sh
npm run prepare:performance-fixture
npm run build
npm run test:windows-release-matrix
npm run test:windows-release-interaction
npm run test:windows-performance -- --baseline-only --quality=fast --samples=1025 --force-integrated --quick
```

`--quick` 仅用于流程和显卡路径验证，不作为正式性能结果。正常矩阵每组使用独立配置与测试工程；报告保存硬件、电源、窗口、DPR、输入身份、绘制尺寸、面数和有效状态。

## 限制与结论

第 6 步的本机固定输入性能目标达到：默认流畅档 513²／1025² 空场景操作约 60 FPS，完整固定示例约 60 FPS、高于至少 30 FPS 的目标；本机另外两档也记录到约 60 FPS。交付已更新的原 Windows 便携版、功能回归、发布说明与原始矩阵，不把它概括为全量测试无失败或所有地图性能已完成。

第 5 步首次模型编译和个别元数据提交尖峰仍保留；其他设备、更多树草／模型、全图大笔刷、真实 Cocos 导入／运行和成品美术不由本机固定样例结果证明。只有核显时的 1025² 预检未达 60 FPS，应与最终独显默认路径分开报告。
