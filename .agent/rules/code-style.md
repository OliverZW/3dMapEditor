# 代码规范

适用：TypeScript、React、着色器、Worker、测试、脚本与构建配置。模块依赖见 [架构规则](architecture.md)，视觉呈现见 [整体风格](visual-style.md)。

## 类型与命名

- TypeScript 启用严格检查；外部输入使用 `unknown` 并校验，不用 `any` 绕过类型约束。
- 类型、接口和 React 组件使用 PascalCase；变量、函数与 Hook 使用 camelCase，Hook 以 `use` 开头。
- 组件文件与组件同名，其他 TS 文件采用 kebab-case；保持同类文件的命名一致。
- 名称表达领域含义和必要单位，明确区分 world、hex 与 sample 坐标。
- 公共接口明确输入、输出、边界与失败形式；类型导入使用 `import type`。
- 注释解释算法原因、坐标约定、精度与不变量，不逐句复述代码；业务说明使用中文。

## 可读性与模块化

- 按职责组织模块；界面展示、编辑用例、拾取算法和渲染资源各有清晰入口，避免持续堆积大文件。
- 函数职责单一，使用明确的领域名称；复杂模式使用有含义的状态类型，避免互相矛盾的布尔标记。
- 只提取实际复用或职责独立的模块，不为尚未实现的功能创建占位层。
- 删除被替代的组件、分支、状态、样式、导入和依赖；禁止未使用的孤儿代码。
- 开启 TypeScript 未使用检查，并检查模块引用；动态加载、平台扩展和外部约定入口须核实调用路径，不能仅凭静态搜索误删。

## 组件与状态

- React 使用函数组件，状态保持最小，不重复缓存可推导数据。
- UI 经应用层发起用例，不直接改写核心数组或将 Three.js 对象作为持久化数据。
- 高频笔刷、相机和渲染循环不逐帧驱动 React 重渲染，面板订阅节流后的显示状态。
- Effect、事件、订阅和异步任务都有清理路径，不在组件渲染过程中创建持续运行资源。

## 错误与资源

- 导入、解码和文件操作返回可定位的错误，禁止空 catch、静默丢弃数据或失败后部分切换工程。
- 用户输入、文件内容和 Worker 消息先做运行时校验，不能仅依赖静态类型声明。
- 异步结果校验工程/任务版本，取消或失败不得污染正式数据和历史。
- 显式释放 GPU 资源、位图、临时 URL、订阅和线程，共享资源按引用管理。
- 随机结果可复现，重做和重开不得改变已保存分布。

## 验证与维护

- 测试覆盖行为、边界、确定性和失败保护，不镜像实现；按变更风险选择核心测试与浏览器交互验证。
- 新依赖先检查已有能力，选择兼容版本并锁定；依赖变更限于任务需要，避免无关升级。
- 记录实际执行的命令与结果，不虚构构建或测试结论。
- 功能、接口或交互变化时同步相关需求、设计、规则与引用，保持单一准确来源。
- 通用约束放入 rules；工作进度、待办、审核记录和实施顺序放入 docs，不混入本文件。
