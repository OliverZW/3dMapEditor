# 地图工程目录与专属文件规范

规范版本：2；更新日期：2026-10-31。关联：[资料索引](README.md) · [技术设计](technical-design.md) · [目录现状](project-directory-guide.md)。

**状态：第 1 步已提供平台无关的目录编解码、存储接口和 v4 备份实现；第 2 步增加原生 Windows 目录适配和现有打开/保存入口，首页与完整创建流程仍待后续步骤。** 内部地图数据版本保持 3、生成器版本保持 1；备份版本为 4，不再接受旧版 v1～v3 `.map3d`。实际验证见[实施记录](implementation.md)。

本项属于编辑器开发，不制作地图，不迁移现有地图或共享素材。目标为 Windows 桌面应用、一工程一地图、独立工程文件夹；执行顺序见[新版本计划](new-version-plan.md)。

## 1. 工程目录与归属

```text
我的地图/
├─ project.map3dproj           工程入口文件
├─ data/
│  └─ <保存版本>/
│     ├─ map.json              地图参数、材质配置、资源描述及 nextId
│     ├─ objects.json          树木、河流、据点、势力及草层描述
│     ├─ builtin-lock.json     内置素材引用及内容哈希
│     ├─ terrain/
│     │  ├─ base.f32           基础高度
│     │  └─ surface.rgba       四通道地表权重
│     ├─ logic/
│     │  └─ owners.u32         六边形据点归属
│     └─ grass/
│        └─ <layerId>.f32      草层密度
├─ assets/
│  ├─ models/<hash>.glb        工程导入的自定义模型
│  └─ textures/<hash>.png      工程自有贴图
├─ exports/                   Cocos、高度图等导出结果
├─ backups/                   用户主动生成的 .map3d 备份
└─ .editor/
   ├─ recovery/               未正式保存的恢复草稿
   ├─ cache/                  可重建缓存、缩略图及派生资源
   └─ workspace.json          镜头、面板和临时显示状态
```

- 位置由用户选择，独立于编辑器源码、安装目录和测试输出；目录名称不作为工程身份，也不决定地图名称。
- 新建仅创建入口、首个保存版本及其必要文件；草层、工程自有素材、导出、备份和会话目录按需生成。新建不复制全部内置素材。
- `data` 保存不可变的完整数据版本，不是增量补丁。入口决定当前版本，不能通过目录时间或名称猜测最新版本。
- `assets` 是工程自己的资源；内置素材从编辑器共享资源库读取。自定义资源来源路径仅作说明，不参与加载。
- 正式打开只读取入口及其声明的数据和资源；不扫描 `exports`、`backups` 或 `.editor` 作为地图内容。

## 2. 专属入口与数据文件

### 工程入口 `.map3dproj`

固定文件名为 `project.map3dproj`，编码为 UTF-8 JSON。字段结构如下（目录存储接口已实现，原生打开入口待第 2、3 步）：

```json
{
  "format": "map3d-project",
  "projectVersion": 1,
  "projectId": "293da521-01a2-4581-8a70-f47d12cb465b",
  "name": "我的地图",
  "dataRevision": "0737d548-97ba-41e3-86e5-df5750c67735",
  "previousDataRevision": null
}
```

- `projectId` 为创建时分配的 UUID；改名、保存、移动目录均保留此 ID。普通目录复制视为同一工程副本。
- `name` 是地图名称的唯一持久化来源，去除首尾空白且不能为空；地图改名不要求修改入口或工程目录的名称。
- `dataRevision` 是当前保存版本的 UUID，对应 `data/<dataRevision>/`；`previousDataRevision` 为上一个成功版本，首存为 `null`。版本值只能是 UUID，不接受任意路径。
- `projectVersion` 独立于地图数据格式、生成算法版本、`.map3d` 备份版本和引擎导出版本；未知入口版本必须拒绝。

### 正式数据

- `map.json` 保存地图数据格式／生成算法版本、宽长、采样、高度范围、逻辑网格、材质配置、资源描述及 `nextId`；不重复保存工程名称或工程身份。地图数据版本仍为 3，与 v4 备份容器版本独立。
- `objects.json` 保存树木实例、河流参数、城池／要塞、势力和草层描述；草层以稳定 ID 关联密度文件。
- `base.f32` 和草密度使用小端 Float32；`owners.u32` 使用小端 Uint32，0 表示无归属；`surface.rgba` 为四通道字节权重，每个采样点四通道和为 255。数组按行存储，沿用 Y 向上、XZ 平面、米制和图片向下为 +Z 的约定。
- 地图数据保存基础高度，不保存河床合成后的最终高度、水面网格、渲染对象、缓存和撤销历史。打开后重建派生结果，保留原有对象 ID、草种子和算法版本。

### 资源引用与共享锁定

- 资源描述必须明确为共享内置资源或工程自有资源，不能仅以运行时是否已有 `bytes` 判断归属。共享引用记录资源标识及 SHA-256；工程自有引用记录内容哈希及工程根目录相对路径。
- `builtin-lock.json` 为 `{ "version": 1, "resources": [...] }`，记录当前地图实际依赖的模型、地表、水面资源的类型、标识和 SHA-256；纯内置库浏览列表中未使用的模型不算地图依赖。锁文件与地图中的共享引用必须一致。
- 共享库按标识与内容哈希共同匹配，缺失或哈希不符时报告具体资源并阻止切换工程；不以同名、最新版本或默认资源静默替代。更新共享库不能自动改写旧工程的锁定记录。
- 自定义静态模型保存在 `assets/models/<hash>.glb`，纹理自包含于 GLB；独立工程贴图保存在 `assets/textures/<hash>.png`。同内容在工程内只存一份，路径与内容哈希须匹配。目录规范不代表已经增加自定义地表／水面导入工具。
- 地图材质尺度、强度等参数归地图数据，不写回共享素材默认配置。内置 LOD 等可重建派生资源不属于必备地图原始数据。
- 资源路径使用 `/` 和工程根目录相对路径；拒绝绝对路径、父目录穿越及解析后逃出工程根目录的链接。共享资源以标识解析，不保存编辑器安装目录的绝对路径。

## 3. 新建、保存、打开与恢复

### 新建

填写名称、父目录、宽长和采样数；默认 2048×2048 米、513×513 采样、初始高度 32 米，高度范围 0～256 米，另支持现有的 1025×1025 采样。宽长沿用每边 1～16384 整数米及现有网格预算约束。

在选定位置创建独立工程目录；目标目录已存在时拒绝覆盖，即使为空也不复用。默认创建空白地图，首层地表权重为 255，树草、河流、据点和势力为空。第 3 步增加默认不勾选的“导入示例工程”，勾选时使用示例参数创建具有新身份的独立副本，不修改模板。只有首版数据与入口全部成功落盘后，才切换当前工程。

### 正式保存

1. 确认或取消当前预览，提交已完成笔触，取得一致的文档快照；同一工程的正式保存串行执行。
2. 分配新的保存版本，先写入新增的不可变素材及完整数据目录，不覆盖入口指向的旧数据。
3. 校验候选版本的数组、数值、对象引用、资源哈希、共享锁与路径及资源预算，确认文件写入成功。
4. 在工程根目录写入临时入口，以原子替换提交为 `project.map3dproj`；同时更新当前及上一个成功版本的指针。平台不能提供该提交保证时，不得声称保存成功。
5. 入口提交成功才标记对应快照已保存；保存期间发生的新编辑仍标记为未保存。后续成功保存后，只清理不属于当前或上一个成功版本的工程生成数据目录；清理失败单独提示，不撤销已经成功的提交。

保存中断或失败保留上次成功入口和数据。没有被入口提交的版本不是正式保存，也不在打开时自动选用。首版不自动清理 `assets`，避免删除旧版本或恢复草稿仍需的素材；不以此流程清理用户目录或工程外文件。上一成功版本用于故障恢复，不代替用户备份或持久化撤销历史。

### 打开与恢复

- 从入口读取候选工程；先校验格式、版本、文件存在性、长度、有限数值、数组预算、对象与资源引用、哈希及路径，全部通过才整体替换会话。失败保留正在编辑的地图。
- 新建、打开及切换工程沿用未保存修改的保存／放弃／取消保护（界面接入在后续步骤）；切换失败不清除原有历史和未保存状态。
- `.editor/recovery` 保存工程身份、基线版本和恢复所需数据及资源引用；用户选择恢复后成为未保存编辑内容，不自动覆盖正式入口。不自动恢复其他工程或基线不匹配的草稿。
- `.editor/workspace.json` 仅保存镜头、面板和临时显示状态，不进入地图内容历史；不存在或损坏时使用默认会话状态。缓存、会话文件和导出结果丢失不影响正式工程加载。

## 4. v4 自包含备份与资源契约

`.map3dproj` 是工作目录入口；`.map3d` 是自包含 ZIP 备份，二者不可混用。

```text
manifest.json              { format: "map3d-backup", formatVersion: 4, name: "地图名称" }
map.json                   内部数据版本、生成器版本、设置、网格、nextId、模型与材质描述
objects.json               树木、草层描述、河流、据点、势力
builtin-lock.json          原快照的共享依赖清单
terrain/base.f32           小端基础高度
terrain/surface.rgba       四层地表权重
logic/owners.u32           小端归属数组
grass/<layerId>.f32        小端草密度
assets/models/<hash>.glb   备份实际依赖的模型及工程自有模型
assets/textures/<hash>.png 地表和水面原始贴图
```

- 目录数据与备份复用同一套编解码。目录的三个 JSON 和二进制数据位于 `data/<revision>/`，工程自有素材位于根目录 `assets/`；备份数据文件位于 ZIP 根目录，没有工程入口文件。
- 模型与每个图片描述均存储 `resource`：共享为 `{ origin: "builtin", id: "分类/资源文件" }`，自有为 `{ origin: "project", path: "assets/.../<hash>.<ext>" }`；描述自身包含 `hash`。持久化描述不包含运行时 `bytes`。
- 锁清单条目为 `{ kind: "model" | "surface" | "water", hash, resource }`，只记录共享引用，去重并稳定排序，须与地图引用完全一致。未使用内置模型仅属于可选浏览列表，不写入数据或备份；工程自有模型保留。
- `waterMaterial` 保存 `version=1`、`normal`、`mask` 及 `material` 的颜色、粗糙度、金属度和透明度。水面 PNG 接受非交错灰度或 RGB/RGBA8，地表保持 RGB/RGBA8；两者均校验哈希、尺寸、PNG 块和解码预算。
- 备份收齐所有已记录资源，即便原快照是共享引用。恢复先按原引用验证锁和包内字节，再将资源显式变为工程自有，不依赖原目录或当前共享库；之后保存为目录工程也不重新共享化。水面渲染和引擎导出消费文档资源。
- ZIP 输入最多 256 MiB，解压文件总量最多 512 MiB、4096 个文件；JSON 单文件最多 16 MiB。拒绝重复路径、绝对路径、父目录穿越和反斜杠；模型与贴图还受原有独立预算限制。
- v1～v3 包及未知版本一律拒绝，不迁移、不转换、不覆盖原文件。目录入口、内部地图数据、算法、备份及引擎导出版本独立管理。
- 复制工作目录至少带上入口、当前数据版本和 `assets`，仍需匹配的共享内置素材；保留上一成功版本须同时复制该版本。跨电脑或独立备份优先使用完整 v4 包。

## 5. 存储适配与会话契约

- `ProjectStorage` 的所有路径相对选定根目录。适配器提供独占建根、带预算读取、不可覆盖写入、比较并原子替换、列出目录文件和移除文件；必须阻止解析后逃出根目录的链接。真实 Windows 适配由第 2 步的 NativeProjectStorage 提供，详见[桌面开发](desktop-development.md)。
- `ProjectRepository` 提供 `create/open/save/backup/restore`，输入先取快照，打开和恢复仅返回验证后的候选文档，不直接修改编辑会话。入口原子比较可拒绝其他会话的覆盖保存。
- 保存返回 `savedRevision` 和 `warnings`，应用层只能将对应编辑版本标记已保存；保存成功后的旧版本清理失败仅为警告。清理只针对之前入口已知的过期版本中的标准数据文件，不清理 `assets` 或用户添加的其他文件；中断产生的未提交版本不自动打开。
- `.editor/recovery/current.json` 记录工程身份、基线保存版本和不可变 v4 草稿路径。恢复须匹配当前正式入口和记录中的身份、基线，返回未保存文档，不改写正式数据；由后续 UI 让用户选择。
- `.editor/workspace.json` 保存相机位置/目标、面板开关和显示开关，最多 64 KiB；缺失或损坏返回默认状态，不影响正式工程。

## 6. 验证边界

第 1 步使用内存适配器测试目录往返、故障注入、原子提交契约、资源锁、资源预算、草稿隔离和备份独立恢复。测试结论与实际命令见实施记录；第 2 步补充原生 Windows 文件系统、中文路径、权限失败与桌面关闭流程检查，结果见实施记录；不代表断电持久性、网络盘或安装包已经验收。后续步骤继续执行对应平台和 UI 验收。
