# Windows 发布版性能基线与 GPU 诊断

日期：2026-11-01。关联：[性能分步计划](windows-performance-plan.md)第 1 步 · [桌面运行方法](desktop-development.md#发布版性能诊断) · [实施记录](implementation.md) · [历史渲染报告](render-optimization.md)。

本轮属于所有地图共用的编辑器诊断能力，不制作地图作品，不执行计划第 2～6 步，不改变正常启动时的画质或 GPU 选择。

## 可复现方法

运行 `npm run build` 更新原 `dist/mapEdtor-v<版本号>/`，关闭该目录中正在运行的程序后执行 `npm run test:windows-performance`。工具通过真实 Electron EXE、正式打包资源、完整编辑界面及受限 preload 运行，不使用 Vite 或独立裸画布代替发布版。

- 工具生成独立临时配置和两张测试地图：通过首页创建的 513²、2048×2048 米空白工程，以及勾选内置示例后创建的独立副本。保存工程入口哈希及 `app.asar` 哈希；同次运行所有对照复用相同地图，不改动对象、采样或原始资源。
- 内容窗口请求 1600×1000；Windows 实际窗口、显示器及绘制缓冲以报告为准。固定透视相机位置 `[700,870,1050]`、目标 `[0,32,0]`。每项预热 5 秒、采样 15 秒、重复三轮，各轮轮换对照顺序；每项重建并释放视口，等待地表和模型异步加载完成。
- 静止对照为现有地表、隐藏地形、无光照材质、像素比 1、现有像素比减半、关闭 MSAA。无光照材质保持原地形几何及其他场景对象；分辨率测试不改抗锯齿，抗锯齿测试不改分辨率。像素比 1 若等于设备原值，报告应按无变化对照理解。
- 两张地图另测当前画质相机运动：相机与目标沿 X 轴按 `sin(t秒)×80米` 同步平移，保持朝向。此为程序驱动的运动夹具，不代替后续真实输入和连续笔刷验收。
- 测试窗口保持前台，失焦、后台、文档变化及上下文丢失会使结果无效；软件渲染或 WebGL 加速禁用时停止建立正式基线，先处理图形路径。
- `--quick` 只验证采样流程；`--baseline-only` 只测当前画质的静止及运动；`--force-discrete` 为单独的启动参数对照，不会写入系统设置或成为产品默认值。方法依据 [Electron 官方 GPU 选择参数](https://www.electronjs.org/docs/latest/api/command-line-switches#--force_high_performance_gpu)，是否生效必须核对实际 WebGL renderer，不能只看参数已传入。

## 指标与限制

- FPS 按实际渲染帧起始间隔计算，P95 使用最近秩百分位；每个样本保留均值、中位数、P95、最大值和样本数。三轮汇总使用各轮指标的中位数，原始各轮结果分别保留。
- CPU 帧墙钟时间覆盖渲染循环中的场景更新和提交；render 提交墙钟时间单独记录。它们可能包含驱动等待，不是 CPU 利用率，不能与 GPU 时间相加。
- GPU 时间通过 `EXT_disjoint_timer_query_webgl2` 异步读取；查询队列上限 8，不同步等待。时钟 disjoint 时丢弃待处理查询并记录次数；扩展不可用时为 null。结束时尚未返回的查询释放，不伪造样本。
- 总面数取 `renderer.info.render.triangles`，包含实际提交的地形；模型面数沿用现有每秒发布的颜色通道统计，明确标注节流，不包含地形、水和辅助图形。Draw／面数不包含 DOM 合成；GPU 查询覆盖 WebGL 场景提交，不包括完整桌面合成成本。
- 隐藏地形、无光照材质、分辨率和 MSAA 对照仅用于归因，不能作为完整画质的达标结果。诊断重建、截图与首次加载均在采样区间外；诊断计时本身仍有开销。
- 正式帧率目标仍属于后续优化与集成验收，本步不以采集工具通过宣称空场景 60 FPS 或完整示例 30 FPS 已实现。

## 诊断入口与资源边界

只有主进程收到显式环境开关 `MAP_EDITOR_PERFORMANCE_PROBE=1` 时，才向 preload 传递固定诊断标识；App 随后动态加载采样模块。正常启动不安装诊断对象，默认像素比、MSAA、阴影及材质保持原值。

诊断对象只允许读取视口快照、选择固定对照项及限时采样，不暴露应用 session、Node、任意 IPC 或文件路径访问。采样结束／失败／关闭视口时恢复渲染方法、移除事件与计时回调、释放 GPU 查询；切换对照释放旧视口和临时材质。临时工程与用户配置隔离。

## 默认启动正式实测

本机为 Windows 10 x64（10.0.19045）、i7-7700HQ、约 16 GiB 内存，接交流电；显示器 60 Hz、125% 缩放。Electron 45.2.1／Chromium 156。默认实际使用 Intel HD Graphics 630、驱动 31.0.101.2114、ANGLE D3D11，WebGL 和 GPU 合成均启用。系统还识别到 GTX 1050（驱动 31.0.15.2686），默认启动时未激活；不是软件渲染回退。

实际视口 CSS 尺寸 1038×873，默认像素比 1.25，绘制缓冲 1297×1091，MSAA 4 样本。原画质保持 PCF 阴影及现有地表。空场景实际为 1 Draw、524,288 个地形三角形、0 模型面数；完整示例存储 946 棵树、2 座据点、1 条河和 1 层草，静止视角有效树 870 棵、生成草 10,483 株，51 Draw、总面数 772,141、模型面数 195,183。

正式报告：[默认启动三轮完整矩阵](../../test-results/tests/windows-performance-2026-11-01T03-30-53-617Z/report.json)。共 42 段有效采样，无采样错误；下表为三轮中位数，GPU 列单位 ms。

原画质静止空场景 CPU 帧墙钟中位数 0.40 ms、render 提交 0.20 ms、P95 帧间隔 176.70 ms；完整示例分别为 1.60／1.40／118.30 ms。原画质相机运动时，空场景 10.64 FPS、P95 105.00 ms；完整示例 8.91 FPS、P95 363.90 ms。运动仍包含实际裁剪、LOD 判断及草中心更新，不把静止 CPU 耗时代替编辑响应。

## 独显启动正式对照

先以 `--quick --baseline-only --force-discrete` 确认实际切换成功，再以 `npm run test:windows-performance -- --baseline-only --force-discrete` 完成三轮正式对照。正式报告：[GTX 1050 原画质基线](../../test-results/tests/windows-performance-2026-11-01T03-49-13-563Z/report.json)，12 段有效采样、无采样错误；[独显短测](../../test-results/tests/windows-performance-2026-11-01T03-48-21-143Z/report.json)独立保留，不混入正式汇总。

正式对照使用同一 `app.asar`、地图生成方式、相机、窗口、1297×1091 绘制缓冲、4 样本 MSAA、阴影及现有地表；只对该次启动添加 `--force_high_performance_gpu`。实际 WebGL 与 Electron GPU 信息均确认使用 NVIDIA GeForce GTX 1050／ANGLE D3D11，不能将其与默认 HD 630 的结果合并。

| 原画质场景 | 默认 HD 630 FPS | GTX 1050 FPS | GTX 1050 GPU ms | GTX 1050 P95 帧间隔 ms |
| --- | ---: | ---: | ---: | ---: |
| 空场景静止 | 10.56 | 60.05 | 4.53 | 16.80 |
| 空场景相机运动 | 10.64 | 60.05 | 4.49 | 16.80 |
| 完整示例静止 | 9.03 | 60.05 | 5.46 | 16.80 |
| 完整示例相机运动 | 8.91 | 55.25 | 5.52 | 36.30 |

完整示例运动仍有短时卡顿，三轮最大帧间隔约 61.7～63.3 ms，CPU 帧墙钟最大值约 40.6～43.9 ms；不将平均约 55 FPS 解释为持续每帧 16.7 ms，具体长任务留待第 5 步剖析。

本机现阶段可在关闭已打开的编辑器后，以 PowerShell 从工程根目录显式启动独显模式：

```powershell
& '.\dist\mapEdtor-v0.2.0\ShanheMapEditor.exe' --force_high_performance_gpu
```

已有实例必须先关闭，否则单实例机制可能只激活旧进程，启动参数不会重新选择显卡。该方式已在本机对照确认，不改 Windows 图形设置、不降低画质；双击 EXE 的默认行为尚未改成强制独显。

## 归因与后续边界

默认核显路径下，空场景 CPU 帧墙钟远小于 GPU 时间，同几何的无光照地表显著提速，支持主要瓶颈在当前地表材质／着色与光照的 GPU 路径。该对照同时移除了复杂材质和光照／收影成本，尚不能进一步声称某一个纹理采样或某一种噪声独占了耗时。降低分辨率或单独关闭 MSAA 均不足以使完整示例达到 30 FPS。

核显已启用硬件加速，但没有使用机器上现有独显，因此需要分别评估显卡选择和核显材质成本。第 1 步只交付诊断及对照，正常启动的 GPU 策略、材质、阴影、抗锯齿和分辨率保持原值；本机独显结果不能代表仅有集成显卡的目标电脑。

本机优先处理实际 GPU 选择即可保留当前画质并显著改善性能，后续接入默认策略时仍需考虑设备及电源条件。仅有集成显卡的 Windows 设备仍需要后续地表简化及显示档位；连续编辑与运行导出性能不以本轮静止／固定平移基线代替验收。
