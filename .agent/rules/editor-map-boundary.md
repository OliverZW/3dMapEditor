# 编辑器开发与地图制作边界

适用于本工程的需求理解、实现、美术调整、示例、测试与验收。现状、案例和目录说明从 [项目资料索引](../docs/README.md) 按需读取。

## 两类任务

- **编辑器开发**：增加或修复可复用的工具、交互、数据结构、渲染能力、资源管理、保存格式及引擎适配；交付软件能力、操作入口和相应验证。
- **地图制作**：使用已有工具与受支持的导入流程，雕刻某张地图、绘制地表、摆放对象、设置归属及已有地图参数；交付可继续编辑的独立地图工程与效果记录。
- 同一需求可同时涉及两者，但必须分别列出所需能力、地图制作步骤、交付物和验收，不以其中一类的完成代替另一类。

## 判断与实施

- 开始前说明本次属于编辑器开发、地图制作或两者兼有，明确影响当前地图、新建地图、共享资源还是所有地图的显示。
- 已能通过现有工具完成的地图效果，优先归为地图制作；不足之处明确为缺失能力、现有能力缺陷或地图内容尚未制作，不能统称为编辑器问题。
- 增加“纹理尺度”控制属于编辑器开发；在某张地图中调整已有尺度属于地图制作。增加自动山脉算法属于编辑器开发；使用现有画刷塑造山脊属于地图制作。
- 不能通过改写启动示例、硬编码特定地图数据、全局灯光或共享素材，冒充只修改了某张地图。脚本生成或直接注入的数据必须说明生成方式，不能作为普通用户操作能力已具备的证据。
- 单张地图的可编辑参数归地图文档，支持相应保存与历史；镜头、临时显示和编辑偏好按既有会话规则处理。新增地图参数及其操作入口本身仍属于编辑器开发。

## 素材、预设与示例

- 共享模型、贴图和默认预设是编辑器提供的资源基础；在地图中选择、布置和调参是地图制作。修改共享资源或默认值须说明对已有工程、新建工程和全局显示的实际影响。
- 启动示例、教学样板、固定测试场景与正式地图作品分别标注用途。测试输出、程序生成示例和研究样板不得自动当成正式地图交付。
- 地图作品、资源来源、测试产物与应用源码分别管理；具体路径和迁移建议写入项目资料，不在通用规则中固化待整理目录。

## 验收与说明

- 编辑器验收检查可操作性、通用性、数据一致性、保存恢复、撤销和资源生命周期；测试通过只证明相应行为，不自动证明成品美术质量。
- 地图验收检查地貌、材质分布、比例、构图、光照及目标观察距离下的效果，并核对已保存工程能恢复；不能只凭工具存在或局部测试截图宣布地图制作完成。
- 画质对比明确使用哪张地图、哪些素材与参数、相机和光照条件，以及编辑器能力和地图内容各自的差距。
- 工作记录分别写清“编辑器能力已完成”和“地图内容已完成”；目录调整另说明实际迁移与仅供讨论的建议，不能混报完成状态。
