# Windows 编辑器性能优化分步计划

确定日期：2026-11-01。关联：[资料索引](README.md) · [Windows 桌面开发](desktop-development.md) · [历史渲染性能报告](render-optimization.md) · [实际实现与验证](implementation.md)。

**本文记录已确定的优化步骤和验收标准，不作为功能完成或性能达标证明；各步实际改动、测量条件、结果及剩余问题写入[实施记录](implementation.md)，并链接对应性能报告。**

## 目标与执行约定

本轮属于所有地图共用的编辑器开发，针对 Windows x64 便携版的持续渲染性能和编辑响应，不制作具体地图。用户已确认流畅优先：以本机真实 dist 发布版为验收对象，空场景操作目标 **60 FPS**，完整固定示例 **至少 30 FPS**。

- 以下六步编号固定。后续指定“性能计划第 N 步”时，仅执行该步及必要的文档同步，不自动执行后续步骤；前置步骤未完成时先说明依赖。
- 保持单片连续地形、原始高度采样及对象数据，不通过删除对象、隐藏原有内容或降低工程采样达标。
- 显示档位属于本机编辑偏好，不修改工程格式、共享素材、地图历史或 Cocos 导出；首轮不迁移 WebGPU。
- [历史渲染性能报告](render-optimization.md)保留原测量条件、结果及当轮保画质约束。本计划允许通过显示档位降低编辑画质，不将历史约束当作本轮禁止降画质的要求，也不改写历史结论。
- 各步分别记录局部收益和整帧收益；待机降耗、CPU 更新、GPU 耗时及操作帧率不相互替代，不把未执行的检查写为通过。

## 第 1 步：建立发布版性能基线与 Windows GPU 诊断

**依赖：** 无。

**交付物：**

- 采集真实 dist 的 GPU、驱动、硬件加速状态、WebGL 后端、Windows 缩放、绘制分辨率、总面数、CPU／GPU 耗时及 P95 帧间隔；区分模型面数与包含地形的总面数。
- 对隐藏地形、简单材质、现有地表、分辨率及抗锯齿进行单变量对照；隐藏或替换仅用于诊断，不作为正式场景达标结果。
- 固定空场景和完整示例的可编辑输入、相机及显示条件，后续各步复用同一基线；报告明确设备、资源规模和测量限制。GPU 计时不可用时明确标记，不用 CPU 提交耗时冒充 GPU 时间。

**验收：** 空场景和完整固定示例均有可复现报告；明确主要瓶颈及测量限制。发现软件渲染时先修复图形路径，再建立基线。

## 第 2 步：增加显示档位，默认流畅优先

**依赖：** 第 1 步。

**交付物：**

- 流畅档：像素比为 `min(DPR, 1) × 0.75`，保持视口宽高比，将绘制缓冲限制在 921,600 像素以内；关闭 MSAA、阴影、地表法线细节，各向异性过滤设为 1。简化地表在第 3 步接入。
- 均衡档：像素比上限 1，保留现有地表表现，阴影尺寸设为 1024，关闭 MSAA。
- 高画质档：保持当前渲染配置，包括像素比上限 1.75、MSAA、2048 阴影及原地表表现。
- 默认选择流畅档，档位保存为本机偏好；缩小的绘制缓冲仅影响三维画面，界面文字保持原有清晰度。
- 切档保留相机、选择和未保存编辑；涉及抗锯齿上下文变化时，通过完整释放并重建视口实现，正确释放被替换的 GPU 资源。

**验收：** Windows 不同缩放下绘制尺寸正确；界面文字清晰，拾取及笔刷坐标准确；切档不修改地图、撤销历史或导出内容，不产生重复渲染循环或资源泄漏。

## 第 3 步：实现流畅档简化地表

**依赖：** 第 1、2 步。

**交付物：** 使用简单漫反射光照、XZ 平面贴图和共享宏观变化纹理；保留四层权重与坡面岩石，移除逐像素程序噪声、法线贴图及三平面采样。均衡和高画质保留原有地表路径，不改写原始贴图及地图材质参数。

**验收：** 同条件记录地表 GPU 时间及整帧收益；检查四层混合、绘制、材质替换及陡坡表现。流畅档接受陡坡纹理拉伸，高画质路径不得新增显示差异。

## 第 4 步：按需绘制与待机降耗

**依赖：** 第 2、3 步。

**交付物：** 无操作、无加载和可见动画时停止无效绘制；相机、笔刷、预览、选择、窗口调整和异步资源就绪立即触发刷新。可见水面和草动画继续调度；统计区明确显示静止状态。

**验收：** 空场景待机不持续提交画面；恢复操作无漏帧更新、残留预览或动画异常。待机降耗与操作帧率分别报告，不能将停止绘制后的统计值作为操作性能结论。

## 第 5 步：治理连续编辑和完整场景卡顿

**依赖：** 第 1～4 步。

**交付物：** 根据剖析定位连续雕刻、最终高度派生、河床、植被贴地及模型更新中的长任务。只对确认的热点实施局部重算或 Worker 调度；复用已有地形缓冲局部更新，异步结果保留工程和任务版本校验。若相关路径未超预算，记录证据，不强行重构。

**验收：** 连续雕刻、相机运动、刷树和据点操作记录帧间隔；撤销重做、取消、快速工程切换和保存重开结果一致，异步旧结果不覆盖新编辑。不以显示网格局部更新时间代替整条编辑流程耗时。

## 第 6 步：集成验收与 Windows 发布

**依赖：** 第 1～5 步。

**交付物：** 构建新的 Windows 便携版，在真实 dist 完成性能和功能回归，更新发布说明、实施记录及性能报告。发布沿用现有便携版构建流程。

**验收：**

- 固定本机硬件、电源、窗口和相机，记录驱动、Windows 缩放、实际绘制尺寸及显示档位；每档预热 5 秒、采样 15 秒、重复三轮。
- 默认流畅档的空场景操作目标为 60 FPS，完整固定示例至少 30 FPS；同时报告 P95，不能用待机结果代替操作性能。其他档位也记录结果，不将流畅档目标混报为高画质档已达标。
- 覆盖 513²／1025²、相机旋转／平移／缩放、连续笔刷、切档、工程往返和资源释放；不同采样及操作结果分别报告，不以平均值掩盖低性能场景。
- 检查低分辨率下拾取和笔刷准确性、地表混合及坡面可读性；高画质路径做同条件画面对照，流畅档按已接受的简化效果验收。
- 未达标时明确剩余瓶颈，不将局部提速标为整体完成。程序验收示例不作为正式地图作品或真实 Cocos 运行性能的完成证明。
