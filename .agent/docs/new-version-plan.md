# 新版本计划：工程入口、自定义素材与 MSI 发布

确定日期：2026-10-31。关联：[资料索引](README.md) · [工程目录规范](map-project-format.md) · [实际实现与验证](implementation.md)。

**本文记录已确定的需求和分步验收标准，不作为功能完成证明；各步实际改动和验证结果以[实施记录](implementation.md)为准。**

## 目标与执行约定

本轮属于编辑器开发，影响启动入口、工程存储、工程自有素材和桌面发布，不制作具体地图。仅交付 Windows x64 MSI，不发布 Web 版。

- 以下七步编号固定。用户说“实现第 N 步”时，仅实施该步及必要的文档同步，不自动执行后续步骤；前置步骤未完成时先说明依赖，不擅自扩展范围。
- 各步完成后在[实施记录](implementation.md)记录实际改动、验证结果和剩余问题，本文保持需求与验收来源，不将未执行的检查写为通过。
- 新版使用 `.map3dproj` 文件夹工程与自包含 v4 `.map3d` 备份；不兼容 v1～v3 `.map3d`，不提供读取、迁移或转换，遇到旧版明确拒绝并保留当前会话。
- 本计划取代既有设计中的旧包兼容、旧包转换及仅空白新建要求；其他目录和可靠保存约束继续沿用。实施对应步骤时同步修订原规范及受影响引用，当前运行版本的行为仍以实施记录为准。
- 不增加 FBX/OBJ 导入、模型独立换贴图、地表粗糙度通道、自动更新或证书签名。

## 第 1 步：工程格式与存储

**依赖：** 无；以现有地图数据和工程目录规范为基础。

**交付物：**

- 实现 `project.map3dproj` 入口、版本化完整数据、工程身份、内置资源锁、自有资源、恢复草稿和会话状态；一工程一地图，路径以工程根目录相对路径表达。
- 新增独立于 UI 和 Electron 的工程存储接口，覆盖创建、打开、保存、备份和恢复，通过存储适配执行读写，不让核心依赖平台文件 API。
- 显式区分共享内置与工程自有资源，按 SHA-256 校验和复用文件；缺失或哈希不符不得静默替换。
- 保存先写候选资源和数据并校验，再原子提交入口；串行保存，保留当前和上一成功版本，保存期间的新编辑仍标记未保存。
- 补齐并实现 v4 备份字节布局和资源清单契约，收齐实际依赖的原始模型、地表和水面资源，恢复不依赖原目录或本机共享库。
- 移除旧包解码与迁移分支，更新旧包兼容要求；保留当前实现状态与新版目标的区别。

**验收：** 数据及资源序列化往返一致；非法路径、未知版本、超预算、资源缺失及哈希错误可定位；模拟各保存阶段失败后上次成功版本可打开；旧包拒绝且不污染会话；原目录和共享依赖不可用时新版备份仍能恢复。

## 第 2 步：Windows 桌面基础

**依赖：** 第 1 步。

**交付物：**

- 接入 Electron，复用 React/Three.js 界面与地图逻辑，完成桌面开发启动入口；本步不制作 MSI。
- 主进程负责原生目录选择和工程文件操作，通过受限 preload 接口调用；渲染进程关闭 Node 集成并启用上下文隔离。
- 实现第 1 步存储接口的 Windows 适配、入口原子替换及中文路径支持；不新增浏览器目录读写适配。
- 实现应用关闭时的保存、放弃、取消保护；保存失败不得继续关闭。明确会话和 GPU 资源释放路径。

**验收：** 桌面开发入口可启动和编辑，原生目录工程创建、保存、重开正常；取消文件选择无副作用；中文路径和权限失败可正确处理；未保存退出的三个分支符合预期。

## 第 3 步：首页与工程创建

**依赖：** 第 1、2 步。

**交付物：**

- 启动显示首页，包含“创建工程”、近期工程及次要“打开工程”入口；无记录时隐藏近期区域，不自动进入示例。
- 近期工程在应用用户数据目录持久化，保留最近成功创建或打开的 10 项，显示名称、位置、最后打开时间，支持移除记录和失效重新定位；打开失败不删除记录。
- 新建填写名称、父目录及地图参数，默认按工程规范创建空白地图，拒绝覆盖已有目标目录。
- 增加默认不勾选的“导入示例工程”。勾选后以现有启动示例的只读模板创建副本，显示并禁用示例尺寸及采样参数，名称和保存位置仍由用户填写。
- 示例副本使用新工程身份，复制可编辑数据和必要自有资源并锁定内置依赖，不复制历史、草稿、缓存和近期记录；不修改模板或其他副本。
- 创建和校验全部成功后才切换会话并加入近期记录；失败不留下有效工程入口。新建、打开和返回首页复用未保存保护。

**验收：** 首次启动、近期排序和重新定位正常；空白工程无示例内容；示例副本可独立编辑、保存和恢复，身份独立；创建失败和取消切换保留原会话；未保存修改在各入口均受保护。

## 第 4 步：完善模型导入与选择

**依赖：** 第 1～3 步。

**交付物：**

- 完善静态 GLB 导入确认，提供预览、名称、分类、比例、旋转和贴地偏移，沿用现有大小、纹理尺寸和静态内容校验。
- 分类覆盖树木、草丛、城池、要塞，资源面板同时展示内置和工程自有资源，导入后可直接选择使用。
- 树木和草丛工具使用所选模型；城池、要塞支持创建时选择模型及替换已选据点模型，替换保留据点身份、位置和归属。
- 模型按哈希保存到工程，重复内容复用资源文件；被使用资源禁止直接删除并显示引用位置。
- 正式变更支持撤销重做，异步导入校验工程版本，失败、取消及过期结果不污染当前工程；释放预览资源。

**验收：** 各分类自定义模型可用；据点替换和撤销重做保持身份及归属；取消和非法 GLB 不产生半成品；保存重开、备份恢复后模型及参数一致。

## 第 5 步：地表贴图导入与选择

**依赖：** 第 1～3 步；复用第 4 步形成的资源面板交互。

**交付物：**

- 支持 PNG/JPG 颜色贴图和可选法线贴图，缺省使用平面法线，统一保存为 PNG；单边最多 4096 像素，同组贴图尺寸须一致。
- 导入提供预览、名称和米制平铺尺度，资源按内容哈希保存在工程内。
- 草地、泥土、岩石、沙地四层分别选择内置或自定义材质，替换不改变既有权重，支持预览取消、撤销和重做。
- 地形继续使用连续高度场；不增加材质层数和粗糙度通道。材质参数归当前工程，不改写共享资源默认值。
- 同步保存、备份、恢复和引擎导出的资源装配，完善引用删除保护和纹理释放。

**验收：** 仅颜色和颜色加法线均可导入；非法图片、尺寸不符和超限均明确拒绝；四层替换保留权重；取消、撤销、重做、重开和备份恢复结果一致。

## 第 6 步：功能集成验收

**依赖：** 第 1～5 步。

**交付物：**

- 执行类型检查、相关单元测试、桌面交互测试及引擎导出资源和协议回归，修复本轮能力的集成问题。
- 验证工程完整往返：高度、地表权重、材质、模型、对象 ID、草分布、归属及资源引用保持一致。
- 验证中文路径、目录移动、示例副本独立性、旧格式拒绝、保存中断、资源损坏、权限失败和异步任务过期保护。
- 同步需求、工程规范、操作说明和实际实施记录，明确验证环境、结果和未验收事项；不把测试场景当正式地图作品。

**验收：** 上述功能通过相应检查；新版备份在原工程不可用时独立恢复；撤销重做与重新打开结果一致；引擎导出不丢自定义资源。真实引擎运行效果不以协议测试代替验收。

## 第 7 步：构建 CMD 与 MSI 发布（历史计划，已由便携版取代）

**依赖：** 第 1～6 步；正式构建与安装包工作放在最后。

**交付物：**

- 根目录新增 `构建.cmd`，直接构建 MSI，不提供 Web/Windows 选择菜单；`npm run build` 统一执行类型检查、前端内部资源打包、桌面打包与 MSI 生成。
- 使用 Electron Forge 的 WiX maker，生成 Windows x64、按用户安装的 MSI，提供开始菜单入口与 `.map3dproj` 文件关联。
- 最终发布产物放在 `dist/windows`，安装包包含内置素材和示例模板，附版本号及发布说明。前端资源仅供桌面运行，不发布 Web 版。
- 检查 Node、依赖和 WiX 构建环境，失败显示具体原因并返回非零状态；不接入自动更新和证书签名，卸载保留用户工程。

**验收：** CMD 与 npm 构建均生成 MSI；在无 Node 开发环境的 Windows 机器验证安装、启动、示例创建、保存重开、文件关联打开、升级和卸载，卸载后用户工程仍保留。
